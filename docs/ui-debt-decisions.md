# UI 视觉债务决策记录（ADR）

> 建立于 2026-10-27。目的：把「已知但决定不修」的分歧写成**决策**，而不是留给下一个人当成**事故**再修一遍。
>
> 一句话原则：**成熟的设计系统不是"全部 token 化"，而是"债务被冻结、收敛是刻意为之"。**

## ADR-001 圆角数字命名：保留，分期收敛

**现状**：`--radius-1 / 2-5 / 3 / 4 / 5 / 7 / 9 / 26 / 38` 共 9 个数字名，69 次引用，
占圆角总使用量约 **19%**（362 次）—— 这是四项里**影响面最大的**。

**为什么不能一把梭**：这些数字不全是脏值，要分两类：

- **同心内角**（`1 / 2.5 / 3`）：外框 4–6px 时，内嵌元素用 2–3px 才视觉贴合。
  直接抹成 4px 会破坏"套娃"关系。**保留。**
- **独立外角**（`5 / 7 / 9 / 26 / 38`）：可以收敛到邻近语义档（`sm/2xs/pill` 等）。

**决定**：只收敛「独立外角」；「同心内角」保留并在注释里写明用途。
分批改、每批用 fixture / computed-style 比对兜底，**2× 放大目视**（1px 差在 1× 下看不出）。

**防复发**：R11 已禁止新增数字名圆角（见下）。

### 第一期执行记录（2026-10-27）

**先做分类核查，结果修正了两处误判**：

| token | 引用 | 原判 | 核查后 | 处置 |
|---|---|---|---|---|
| `--radius-5` | 15 | 独立外角 | 小图标按钮（日期格 / 关闭键 / 搜索键，20–28px） | ✅ → `--radius-2xs`(6px) |
| `--radius-7` | 1 | 独立外角 | `.display-preset-btn` 预设按钮 | ✅ → `--radius-2xs`(6px) |
| `--radius-9` | 2 | 独立外角 | **同心内角**：`.tw-card` 用 `--radius-lg`(14px)，`.tw-card-main` 9px ≈ 14 − 5 padding | ❌ 保留 |
| `--radius-26` | 1 | 独立外角 | `.theme-card` 大圆角；24/28 档已删，无合适归宿 | ❌ 保留 |
| `--radius-38` | 1 | 独立外角 | `#themeEffectSection` 超大圆角，同上 | ❌ 保留 |

> **教训**：`--radius-9` 只看数值会被误判成「零散脏值」，但它其实是**外层 14px 减掉内边距后的同心结果**。
> **判断同心关系必须同时看父级圆角与 padding，不能只看自身数值。**

**结果**：数字名 9 → 7；替换 16 处声明 → **23 个元素**圆角 5/7px → 6px（±1px）。
**验证**：computed-style 逐元素比对 —— 23 个元素**仅 `border-radius` 变化**，无其它属性被带动。

**剩余待评估**：`--radius-4`（23 次引用，量大且可能兼作内外角）、
`--radius-1 / 2-5 / 3`（同心内角，保留）、`--radius-9 / 26 / 38`（有理由保留）。

### 第二期执行记录（2026-10-27）：`--radius-4` → 补「刻度空洞」

**核查结论与第一期不同：这次问题出在刻度，不在用法。**

4px 有 19 处声明 / 23 次引用，用途清一色是**小控件、进度条、徽标**：
`.quick-nav-btn::before`、`.arch-cb-box`、`.arch-act-btn`、`.arch-bar`、`.goal-row-bar(-fill)`、
`.progress-bar`、`.tw-card-*` 工具条按钮、`.tw-card-level`、`.weather-btn`、`.weather-city-inline`、
`.wn-rename-btn/.wn-delete-btn`、`.gho-review-btn`、`.catp-close-btn` …

而它**落在 2px(`3xs`) 与 6px(`2xs`) 的正中间**——就近吸附要动 ±2px，比第一期 ±1px 明显得多。

> 更关键：6px 以上是整齐的 2px 间距（6/8/10/12/14/16/18/20），**2→6 是唯一的空洞**。
> 所以「同一个值被手写 23 次」不是 23 处写错，而是**刻度缺了这一档**。

**处置**：新增语义档 `--radius-tight: 4px` 填补空洞，19 处迁移过去，删除 `--radius-4`。
**值不变 → 零视觉变化**（computed-style 2182 元素 **0 差异**）。

> **原则**：当同一个数值被反复手写时，先怀疑「刻度缺失」，而不是批量改用法。
> 前者是修系统，后者是修症状。

**当前数字名剩余 6 个**（均登记在 baseline，R11 阻止新增）：

| token | 值 | 保留理由 |
|---|---|---|
| `--radius-1` | 1px | 同心内角 / 发丝边 |
| `--radius-2-5` | 2.5px | 同心内角 |
| `--radius-3` | 3px | 同心内角（12 次引用） |
| `--radius-9` | 9px | 同心内角（外层 14px − 5 padding） |
| `--radius-26` | 26px | 大圆角，2 处引用，无对应档 |
| `--radius-38` | 38px | 超大圆角，2 处引用，无对应档 |

## ADR-002 间距离群值：冻结，不收敛

**现状**：`9 / 13 / 18 / 30 / 36 / 40 / 44 / 48 / 50 / 56px` 共 **26 处**，
占间距声明约 **2.6%**（token 980 / 裸值 26）。

**决定：不收敛。** 理由：

1. `9 / 13 / 18` 多在组件内部 `padding`，改 1–2px **视觉无收益**；
2. `40 / 48 / 50 / 56` 是大布局 `gap`，改了**会动版面**，风险大于收益；
3. 2.6% 属噪声级，追求 0% 是过度工程。

**正确做法**：加 lint 冻结（R12），并在下次因**其他原因**改到相关文件时顺手对齐（boy-scout 规则）——
比专门排期清理便宜十倍。

## ADR-003 缓动不统一：明确不改

**现状**：`ease`（浏览器标准曲线）×230，`--ease-cn`（cubic-bezier(.22,.61,.36,1)）×4。

**决定：不改，且明确记录「不改」。**

理由：

1. `ease` **不是脏值**，它是标准曲线；"没用你的 token"不等于缺陷——当 token 相对默认值无增益时，
   不统一才是对的。
2. 一次性改 230 处 transition 的缓动 = **全产品手感同时变化**。用户不会报 bug，
   只会说"说不上来，感觉变飘了"——**测试抓不到、截图证不了**。
3. 这类改动必须作为**动效改版项目**（有设计目标、可 A/B、可回滚），不能挂在"token 收敛"名下做。

**何时重做**：只有做整体动效升级时，才把它当设计决策重新评估。

## ADR-004 fallback 冲突 token：删引用而非定义 ✅

**现状**：`--bamboo-background-soft` 被 3 处引用，却有 **2 种不同 fallback**
（`#f6f7f4` 与 `rgba(var(--deep-rgb), 0.08)`）—— 这本身就证明**它从未有过真正的定义**，
各处都在猜。

**决定：不定义它，而是让引用消失**（否则等于把其中一处的猜测合法化）：

| 位置 | 原意图 | 改为 |
|---|---|---|
| `.toast-action-btn` / `.confirm-extra` | 中性面板底 | `--card-bg`（主题化表面） |
| `.catm-migrate-picker .cmp-item:hover` | 悬停淡染 | `--bamboo-background`（主题淡底） |

⚠️ 此项**不是零视觉变化**（原先是 fallback 生效）。已用 computed-style 比对记录实际差异。

## 护栏如何生效（`scripts/lint-css-tokens.mjs`）

| 规则 | 作用 | 基线文件 |
|---|---|---|
| **R11** `no-new-numeric-radius` | 禁止新增数字命名圆角（定义处） | `scripts/css-debt-baseline.json` → `radiusNumericNames` |
| **R12** `spacing-outlier-growth` | 已登记的离群间距值**不得增加**（可减少） | 同上 → `spacingOutliers` |

**ratchet 语义**：低于基线是好事（说明有人顺手收敛了）；高于基线才失败。
这样既冻住债务，又不阻止未来收敛。

**自证有效性**（已实测）：注入 `--radius-13` 与一处新 `18px` →
精确报出 `R11 ×1 + R12 ×1`；还原后恢复绿。

> 初版把这两条误插在「文件遍历循环」内部，导致同一违规被上报 36 次（= 文件数）。
> 已修正为循环外只统计一次。**护栏本身也要被验证，否则它只是噪音。**

## 何时该重做这些决策

出现以下任一「强制触发点」时，才值得重新评估上面所有决策：

1. 引入新的主题引擎 / 动态换肤机制；
2. 把画中卷 UI 抽成独立组件库；
3. 做一次整体视觉改版（此时圆角、间距、缓动应一并重定）；
4. 出现**可量化的用户不适**（例如多人反馈"圆角看着不一致"）。

在此之前：**冻结 + 顺手收敛 + 不排期清理。**

## 护栏 R13：接线三问 + 迁移即删除（2026-10-27）

背景：BambooSelect 接入 4 处 select，其中 2 处（timeline editor、白噪音
`_showInputModal`）事后证实是死代码——「给所有 X 换皮」如果不先验证每个 X
的可达性，一半工作量是给死代码化妆。

### 接线三问（任何「给 X 加功能/接线/换皮」之前必答）

1. **谁调用 X？** —— `grep -rn "X"` 排除 tests 后必须有引用；只有定义 = 死。
2. **入口是哪个用户动作？** —— 从按钮/命令/宿主消息追溯到 X，给出证据链
   （文件:行）。答不出入口 = 不可达。
3. **消费者自己活着吗？** —— 引用 ≠ 可达：X 的唯一消费者可能是死出口
   （timeline 案例：`index.js` 引用了 TimelineEditor，但 `openEditor` 零调用）。
   沿链走到用户动作才算数。

### 迁移即删除

功能从 A 模块迁到 B（如 timeline 渲染迁入 renderers.js）时，**旧实现必须在
同一 PR 删除**。留下的「以后再删」就是 timeline editor——孤儿存活至今。
确需分步时，写 ADR 记录删除计划与日期。

### 工具

- `npm run check:dead-exports` —— 零消费者导出（既有）
- `npm run check:dead-methods` —— 零引用对象方法（本次新增；52 个存量候选
  见 docs/dead-methods.md，快照 + 漂移即失败，强制评审新增项）
- 盲区（同名方法共享判定、属性键、传递性调用图）记录在脚本头注释——
  宁可漏报，不误伤。
