# UI token 收敛方案（交付物 ④）

> 目标：把「有体系但漂移」收敛为「体系可强制」。
> 所有结论均来自 `scripts/ui-token-audit.py` 与 `scripts/ui-component-inventory.py` 的实测数据，
> 刻度取值来自 `webapp/assets/styles/variables.css` 的真实值。

---

## 1. 根因：刻度盖不住实际用的值

这是采用率低下的**真正原因**，不是"开发者不守规矩"。

### 间距

现有 `--space-1..8` = **4 / 8 / 12 / 16 / 20 / 24 / 28 / 32**（4px 步进）。
但硬编码里实际用得最多的是：

| 值 | 次数 | 是否在现有刻度上 |
|---|---|---|
| 6px | **298** | ❌ |
| 8px | 280 | ✅ |
| 10px | **228** | ❌ |
| 4px | 194 | ✅ |
| 12px | 192 | ✅ |
| 2px | **138** | ❌ |
| 16px | 88 | ✅ |
| 14px | **88** | ❌ |
| 3px | **74** | ❌ |
| 5px | **62** | ❌ |
| 1px | **50** | ❌ |
| 20px | 48 | ✅ |
| 7px | 20 | ❌ |
| 24px | 18 | ✅ |

**用得最多的 6px 不在刻度上**，2/3/5/10/14 也不在。开发者想用 6px 只能裸写——
采用率 28% 由此而来。

### 字号：两族并行 + 5 组完全重复

现有 18 个 `--type-*`，实际只有 **13 个不同取值**，存在 5 组完全重复：

| 重复组 | 取值 |
|---|---|
| `--type-base` = `--type-body` | clamp(13,2.8vw,15) |
| `--type-md` = `--type-lead` | clamp(14,3.2vw,17) |
| `--type-xl` = `--type-large` | clamp(18,4.8vw,24) |
| `--type-2xl` = `--type-hero` | clamp(20,5.5vw,28) |
| `--type-display` = `--type-mega` | clamp(24,7vw,36) |

### 圆角：26 个 token，其中 9 个是 ad-hoc 数字名

`--radius-1` `--radius-2-5` `--radius-3` `--radius-4` `--radius-5` `--radius-7`
`--radius-9` `--radius-26` `--radius-38` —— 直接用像素值当名字，属临时补救。
另有 4 个语义别名（card/control/modal/panel/tooltip）是**好的设计**，应保留并推广。

### 阴影与动效（此处结论已于 2026-10-27 更正）

初版本节写「阴影 87 处硬编码 / 0 token、动效 0 定义 0 引用」，**均为错误**，原因是
只按 `--motion-*` / `--dur-*` 前缀检索、且把 `none` 与 var 兜底计入了硬编码。

实测真相：

| 族 | 已有定义 | 采用 | 硬编码 | 采用率 |
|---|---|---|---|---|
| 阴影 | `--shadow-surface/card/elevated/floating`（明暗各一套，variables.css:211-214） | **59** | 16 | **79%** ✅ |
| 动效时长 | `--duration-instant/fast/normal/slow/slower`（100/200/300/500/800ms，:380-384） | **1** | 371 | **0.3%** ❌ |
| 缓动 | `--ease-cn`（cubic-bezier(.22,.61,.36,1)） | 4 | `ease` 等关键字 230 | ≈2% |

→ **阴影体系健康，不必动；动效时长体系完备但几乎无人使用，是全局最大洼地。**

## 2. 收敛原则

1. **先增量、后替换**：新增 token 不改旧值 → 零视觉变化；迁移另做。
2. **值命名优先于序号命名**：`--space-6` = 6px，无需查表，迁移也可机械化。
3. **原语 + 语义别名两层**：原语管取值，语义别名管用途（card/control/panel/modal）。
4. **护栏先行**：没有 lint 拦截，收敛完还会再漂。

## 3. 各刻度族方案

### 3.1 间距：值命名，覆盖全部观测值

**方案 A（推荐先行，零视觉变化）** —— 名字 = px 值，15 档：

```css
--space-1: 1px;  --space-2: 2px;  --space-3: 3px;  --space-4: 4px;
--space-5: 5px;  --space-6: 6px;  --space-7: 7px;  --space-8: 8px;
--space-10: 10px; --space-12: 12px; --space-14: 14px; --space-16: 16px;
--space-20: 20px; --space-24: 24px; --space-32: 32px;
```

覆盖上表全部 Top14 值 → 迁移纯机械（`6px` → `var(--space-6)`）。

**方案 B（后续可选，真收敛）** —— 压到 9 档（2/4/6/8/12/16/20/24/32），
把 1/3/5/7/10/14 吸附到临近档。刻度更干净，但有轻微视觉变化，需基线 diff 验证。

> ⚠️ 冲突处理：现有 `--space-1..8` 是**序号**命名（=4/8/…/32），与值命名冲突。
> 需一次性重映射（385 处引用，脚本化）：`--space-1→--space-4`、`--space-2→--space-8`…`--space-8→--space-32`。

### 3.2 圆角：26 → 8 个原语 + 5 个语义别名

```css
/* 原语 */
--radius-2xs: 2px;  --radius-xs: 4px;  --radius-sm: 8px;
--radius-md: 12px;  --radius-lg: 16px; --radius-xl: 20px;
--radius-2xl: 24px; --radius-pill: 9999px;
/* 语义别名（沿用现有良好设计） */
--radius-card: var(--radius-lg);
--radius-control: var(--radius-sm);
--radius-panel: var(--radius-xl);
--radius-modal: var(--radius-2xl);
--radius-tooltip: var(--radius-xs);
```

迁移映射：1 / 2.5 / 3 → `2xs(2)` 或 `xs(4)`；5 / 7 / 9 → `sm(8)`；
26 → `2xl(24)`；38 → `pill`（38px 已属全圆量级）。

### 3.3 字号：18 → 10 个原语 + 8 个废弃别名

**原语（保留一条族）**：

| token | 取值 |
|---|---|
| `--type-mini` | clamp(8,1.8vw,10) |
| `--type-xs` | clamp(10,2.2vw,12) |
| `--type-sm` | clamp(12,2.6vw,13) |
| `--type-base` | clamp(13,2.8vw,15) |
| `--type-md` | clamp(14,3.2vw,17) |
| `--type-lg` | clamp(15,3.8vw,20) |
| `--type-xl` | clamp(18,4.8vw,24) |
| `--type-2xl` | clamp(20,5.5vw,28) |
| `--type-display` | clamp(24,7vw,36) |
| `--type-display-big` | clamp(32,9vw,48) |

**废弃别名（指向原语，保持兼容，新代码禁用）**：
`--type-body→base`、`--type-caption→sm`、`--type-lead→md`、`--type-large→xl`、
`--type-heading→lg`、`--type-hero→2xl`、`--type-mega→display`、`--type-micro→mini`

### 3.4 阴影：**不新增**（体系已存在且健康，采用率 79%）

`--shadow-surface` / `--shadow-card` / `--shadow-elevated` / `--shadow-floating`
已构成完整 4 级语义梯度（明暗各一套，`variables.css:211-214` 与 :515+）。

剩余 16 处硬编码是 material market 面板自带的**蓝灰投影**（`rgba(16,24,40,α)`），
与竹青语义阴影不同族。是否归并属**视觉决策**，不是纯技术迁移，需单独确认。

### 3.5 动效：**不新增**（5 档已存在，病在采用率 0.3%）

已有 `--duration-instant 100 / fast 200 / normal 300 / slow 500 / slower 800`（ms），
而 371 处硬编码时长的实测分布：

| 实测值 | 次数 | 对应档 |
|---|---|---|
| 200ms | 115 | fast ✅ |
| 150ms | 60 | **无**（卡在 100/200 之间） |
| 300ms | 38 | normal ✅ |
| 180ms | 34 | ≈fast |
| 400ms | 32 | **无**（卡在 300/500 之间） |
| 120ms | 24 | ≈instant |
| 900ms | 24 | **无**（≈slower 800） |
| 500ms | 16 | slow ✅ |
| 250ms | 16 | ≈normal |

→ 现有 5 档覆盖主簇，但 **150 / 400 / 900 三个高频值无对应档**。
**建议不新增档位**，而是吸附到最近档（150→200、400→500、900→800），
在阶段 2 与迁移同批做，并用视觉基线 diff 验证（动画手感会变，必须看）。

> 缓动同理：`--ease-cn` 仅 4 处使用，`ease` 关键字 230 次。
> 统一到 `--ease-cn` 会改变手感，属视觉决策，需单独确认。

> **阶段 1 结论（重要）**：原本设想的"纯增量加阴影/动效 token"**没有内容可加**——
> 两族都已存在。阶段 1 真正剩下的只有间距值命名（但必然伴随 385 处重映射，
> 属阶段 2）与字号双轨清理（属阶段 3）。**即：阶段 1 可以被跳过，直接进阶段 2。**

### 3.6 颜色

- 新增语义 token 覆盖 Top 硬编码色（`#fff` ×37、`rgba(0,0,0,.18)` ×28、
  `rgba(16,24,40,.16)` ×15 等）—— 这些都是 `variables.css` 明文禁止的裸写。
- 新增色一律 `--bm-*` 前缀。

### 3.7 命名规则冲突（需裁定）

lint R10：新增自定义属性须用 `--bm-*` / `--bamboo-*`；`variables.css` **整体豁免**，
旧无前缀名走 `R10_ALLOWLIST` 白名单。

建议：
- 既有刻度族（`--space-*` / `--radius-*` / `--type-*`）保留原名 —— 白名单已放行，
  且分别有 385 / 371 / 526 处引用，重命名收益不抵风险；
- **新增族**（阴影 / 动效 / 颜色语义）用 `--bm-*` 前缀，符合 R10。

## 4. 迁移策略（分阶段，可回滚）

| 阶段 | 动作 | 视觉风险 |
|---|---|---|
| **0. 护栏先行** | 扩展 `scripts/lint-css-tokens.mjs`：新增规则禁止裸写 spacing / radius / font-size / box-shadow（定义处豁免） | 无 |
| **1. 纯增量** | 只新增 token，不改任何旧值、不替换任何使用处 | **零** |
| **2. 机械迁移** | 脚本批量把硬编码替换为 `var()`，按文件分批 | 低（但有） |
| **3. 废弃旧名** | 删除 `--radius-1/2-5/3/26/38/4/5/7/9`、`--type-body/lead/large/hero/mega` 等 | 低 |
| **4. 清理** | 112 个未使用 token 删除；35 个 fallback token 显式化或标注为外部契约 | 无 |

**阶段 2 的硬性要求**：每批迁移后必须跑
`scripts/ui-visual-baseline.mjs` 重新生成截图并与基线 diff，且 `npm run preflight` 全绿，
方可进入下一批。

### 4.1 阶段 0 已执行（2026-10-27）

**关键发现：守门员早就写好了，但从未上岗。**

`scripts/lint-css-tokens.mjs` 已内置 R1（裸圆角）/ R2（裸字号）/ R3-R8（裸白黑）/
R6（阴影裸色）/ R9（transition: all）/ R10（无前缀变量），**但 `lint:css` 退出码为 1
（80 处违规），且不在 `preflight` / `build` / `.husky/pre-commit` 任何一处**。
这才是 `variables.css` 明文禁止的 `#fff` 仍出现 37 次的真因——不是没人写规则，
是规则没通电。

**执行内容**

1. **清零 80 处历史违规**（保值替换，非重设计）：
   - R5/R3/R6（50 处）：`rgba(0,0,0,α)`→`rgba(var(--black-rgb),α)`、
     `rgba(255,255,255,α)`→`rgba(var(--white-rgb),α)`、`#fff`→`var(--white)`，
     数值完全等价。
   - R1（13 处）：映射到**同值** token（3px→`--radius-3`、8px→`--radius-xs`、
     10px→`--radius-sm`、999px→`--radius-pill`…）；仅 11px 无同值项，
     取 `--radius-md`(12px)，**差 1px**。
   - R2（17 处）：响应式 `--type-*` 在桌面端会放大 1–2px（13px→15px），
     故新增 4 个**固定档** token `--bm-type-fixed-{11,12,13,15}`
     （符合阶段 1「只加 token」），零视觉变化。
2. **上电**：`lint:css` 接入 `preflight`、`build`、`.husky/pre-commit` 三道闸。
3. **修复视觉基线不可复现**（顺带发现的硬缺陷）：
   - `utils/quoteService.js` 用 `Math.random()` 抽箴言 → 基线脚本注入确定性 LCG；
   - 竹叶有 **338 个元素在跑连续动画**（`bambooSway1-5`/`leafTremble`/`leafDrift3`），
     `reducedMotion` 只设媒体查询、拦不住 → 改为向 shadowRoot 注入
     `animation:none!important`。两次运行 md5 现已完全一致。

**零视觉变化的硬证明**：把 HEAD 版 `app.html`（改动前构建）与当前版
同页对比 **2191 个元素的 computed style**（color / background / font-size /
border-radius / box-shadow）——**仅 1 个元素不同**（即 11px→12px 那处），其余全等。

**结果**：`lint:css` 退出码 0；`npm run preflight` 全绿。

### 4.2 阶段 2-1 已执行：动效时长采用率 0.3% → ≈91%（2026-10-27）

**先划范围，再吸附**（否则会把环境动画一起改坏）

`animation` / `transition` 简写里**第二个时间值是 delay 不是 duration**；更要紧的是
项目里有一批 **20–45 秒的环境摆动动画**（`bambooSway*` / `leafDrift*` 的周期）。
若无脑把所有时间值吸附到 5 档，竹叶会从"随风轻摆"变成"疯狂抽搐"。故：

- **吸附区间：`0 < d ≤ 900ms`**（UI 反馈区间）
- **保留裸值**：`0ms`（无动效语义，2 处）、`≥1000ms`（环境/长时动效，50 处）

**吸附映射（最近档，平局取更快）**

| 实测值 | → token | 偏差 |
|---|---|---|
| 80/100/120/140/150 | `instant` (100) | −50 ~ +20 |
| 160/180/200/220/250 | `fast` (200) | −50 ~ +40 |
| 260/280/300/320/350/400 | `normal` (300) | −100 ~ +40 |
| 500/600 | `slow` (500) | −100 ~ 0 |
| 700/800/850/900 | `slower` (800) | −100 ~ +100 |

单处最大变化 100ms（≤25%）；平局取更快档（交互反馈宜快不宜慢）。

**结果**：437 处替换、跨 29 个文件；采用率 **0.3% → 87%**
（按声明计 315/363；剩余 48 处裸值即上文有意排除的 `0ms` 与 `≥1000ms`）。
若按「时间值出现次数」计则为 438/480 ≈ 91%。

**验证**（新工具 `scripts/ui-style-diff.mjs`，computed-style 逐元素比对）：

```
元素数: 2182 → 2182
差异元素数: 10
  #177  transitionDuration 0.15s → 0.1s
  #1790~#1992 ×9  .bamboo-card-header  transitionDuration 0.4s → 0.3s
```

即：**只有动效时长变了，color / background / font-size / border-radius / box-shadow 全部零变化。**

> 该脚本初版踩过一个坑：读取前注入了 `transition:none`，把要比较的时长清零 →
> 误报「0 差异」。已修正并写入脚本注释。

> 同时修正了截图基线的定位：headless 下做不到像素级可复现（审计报告 §7 有实测），
> 故把可靠判据正式改为 computed-style 比对，并落成脚本。

### 4.3 阶段 2-2 已执行：间距刻度改为值命名，采用率 28% → 97%（2026-10-27）

**关键决策：值命名（名字 = px 值）**

旧 `--space-1..8` 是**序号**命名（=4/8/12/16/20/24/28/32），与"名字=px"直接冲突。
改为值命名后单趟重映射（`re.sub` 不会二次扫描替换结果，避免 `1→4` 又被 `4→16` 级联）：

| 旧 | 值 | 新 |
|---|---|---|
| `--space-1` | 4px | `--space-4` |
| `--space-2` | 8px | `--space-8` |
| `--space-3` | 12px | `--space-12` |
| `--space-4` | 16px | `--space-16` |
| `--space-5` | 20px | `--space-20` |
| `--space-6` | 24px | `--space-24` |
| `--space-7` | 28px | `--space-28` |
| `--space-8` | 32px | `--space-32` |

**刻度设计来自实测**：948 处裸写、27 个去重值；新刻度 16 档
（1/2/3/4/5/6/7/8/10/12/14/16/20/24/28/32）**精确覆盖 916 处（97%）**——
这也印证了 §1 的判断：旧刻度盖不住 6/10/14 等高频值才是采用率低的真因。

**执行**
- 重命名 394 处引用与定义
- 补全 16 档定义（新增 1/2/3/5/6/7/10/14）
- 裸写 px → `var(--space-N)` 共 **904 处**

**结果：采用率 28% → 97%**（980 token / 26 裸值）

**未覆盖的 26 处**（刻度未收录，按约定保留）：
`9px`(3) `13px`(3) `18px`(9) `30` `36` `40`(5) `44` `48` `50` `56`。
彻底收敛需二选一：加新档（刻度变长）或吸附到邻近档（**有视觉变化**，需基线验证）。

**验证**：`ui-style-diff.mjs` 对照上一提交 → **2182 个元素零差异**
（因全部是"值相等"的保值替换）。`lint` 绿、`preflight` 绿、636 测试通过。

### 4.4 阶段 3 已执行（仅安全子集）：字号 18 → 14、圆角 26 → 24（2026-10-27）

破坏性变更只做"零视觉变化"的部分。删名前必须同时满足：
①引用为 0 或可等值重定向；②定义**逐字**相同；③重定向后 computed-style 零差异。

**字号：删 4 个真等值别名 + 1 个零引用**

| 别名 | 规范名 | 定义逐字相同？ | 引用 | 处置 |
|---|---|---|---|---|
| `--type-body` | `--type-base` | ✅ | 0 | 删除 |
| `--type-lead` | `--type-md` | ✅ | 1 | 重定向后删 |
| `--type-hero` | `--type-2xl` | ✅ | 5（+1 带 fallback） | 重定向后删 |
| `--type-mega` | `--type-display` | ✅ | 4 | 重定向后删 |
| `--type-large` | `--type-xl` | ❌ **4.5vw vs 4.8vw** | 4 | **保留** |

> `--type-large` 是我初版误判为"完全重复"的一对：只比 min/max 会漏掉 vw 系数差异。
> 结论：**判断重复必须逐字比对定义**，不能只看两端值。

**圆角：删 2 个零引用 token**
`--radius-4xl`(24px) / `--radius-5xl`(28px) 引用均为 0 → 删除，并同步更新映射注释。

**踩到一个坑（重要）**：`--type-hero` 有 1 处是**带 fallback** 的写法
`var(--type-hero, clamp(22px, 10vw, 32px))`。重定向正则只匹配 `var(--x)`，
漏掉了它——而该 token 删除后这一处会**改用 fallback**（22–32px），造成视觉变化。
已改为 `var(--type-2xl)`。
> 教训：**删 token 前必须按「裸名」全量搜索（CSS+JS+注释），不能只搜 `var(--x)`**。

**结果**：字号 18 → 14，圆角 26 → 24。
**验证**：`ui-style-diff` 2182 个元素**零差异**；lint 绿；636 测试通过。

**未做（需视觉决策）**：圆角仍有 9 个 ad-hoc 数字名（`--radius-1 / 2-5 / 3 / 4 / 5 / 7 / 9 / 26 / 38`，
其中 7 个有引用）。收敛必然改值（如 3px→2px 或 4px），属**视觉变更**，不在本阶段范围。

## 5. 护栏（防复发，否则收敛完还会漂回去）

1. **lint 拦截裸写**（阶段 0）—— 最关键，没有它一切白做。
2. **活体指南 + 对比度审计进 CI**：任何 token 改动都跑
   `ui-contrast-audit.py`（576 组网格）与浏览器实测，双向校验。
3. **视觉基线 diff**：`docs/ui-baseline/` 作为回归锚点。

## 6. 风险与代价（诚实声明）

- **阶段 2 是唯一有视觉风险的环节**，必须分批 + 基线 diff；不可一次性全量替换。
- **间距值命名会与既有序号命名冲突**，需一次性重映射 385 处引用（脚本化，但仍需视觉验证）。
- **方案 B（间距压到 9 档）会改变布局**，必须单独排期并走完整基线验证，不在本方案第一阶段。
- 本方案**只做设计与新增**，不含迁移执行；执行前需逐阶段确认。
